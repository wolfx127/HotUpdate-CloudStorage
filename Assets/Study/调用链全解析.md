> 说明：本文按“**谁调用谁**”展开，不画时序图。每条链给出调用树和方法明细表，标出方法所属类、调用者、运行线程。

## 0. 先约定三件事

### 0.1 两个“主线程”

| 主线程 | 属于 | 跑什么 |
| --- | --- | --- |
| Unity 主线程 | 游戏客户端（exe / Editor） | 所有 `MonoBehaviour`、协程、UI 事件、`AssetBundle.LoadFromFile`、`Assembly.Load` |
| Node 主线程（事件循环） | 云服务器 | 路由、JSON 解析、`db` 内存对象；文件 I/O 由 libuv 线程池执行，完成后回调事件循环 |

Unity 的 `UnityWebRequest` 传输在引擎原生层异步进行，完成后把协程**恢复回主线程**；Node 的 `await fsp.writeFile` 不阻塞事件循环。两边真正的“游戏代码”都只在自己那条主线程上跑。

### 0.2 参与的程序集

| 程序集                      | 目录                          | 角色                          |
| ------------------------ | --------------------------- | --------------------------- |
| `HotUpdateDemo`          | `Assets/Scripts/Baseline/`  | AOT 主工程（AB 管理、启动、UI、云同步、账号） |
| `HotUpdate`              | `Assets/Scripts/HotUpdate/` | 热更程序集（版本号 + 伤害公式）           |
| `Assembly-CSharp-Editor` | `Assets/Editor/`            | 构建工具（打 AB、写 catalog）        |
| 无（Node）                  | `CloudServer/`              | 账号/存档服务 + AB 静态托管           |

### 0.3 图例

- `类.方法()`：你自己的代码
- `[引擎] 方法`：Unity / Node 内置，不是项目脚本
- `（yield）`：协程在此让出，之后回主线程恢复
- 文件路径均相对项目根

# 一、启动服务器时主线程的调用链

## 1.1 触发点

```powershell
node CloudServer/server.js
```

Node 进程启动，**从上到下同步执行整个 `server.js`**，然后进入事件循环。

## 1.2 调用树

```text
[终端] node CloudServer/server.js
└─ [Node] 模块加载（主线程）
   ├─ 读取环境变量
   │  ├─ PORT           = process.env.PORT || 8080
   │  ├─ HOST           = process.env.HOST || '0.0.0.0'
   │  ├─ API_TOKEN      = process.env.API_TOKEN || 'dev-token'
   │  ├─ CONTENT_ROOT   = ServerData/
   │  └─ DATA_DIR       = CloudServer/data/
   │
   ├─ loadDb()                                   server.js
   │  ├─ emptyDb()                                server.js
   │  ├─ fs.mkdirSync(DATA_DIR)                  node:fs
   │  ├─ fs.existsSync(DB_FILE)                  node:fs
   │  │  └─ fs.readFileSync + JSON.parse
   │  │     └─ normalizeDb()                      server.js
   │  └─ [无 db.json 时]
   │     ├─ fs.existsSync(players.json)
   │     └─ fs.readFileSync + JSON.parse → db.players（旧存档迁移）
   │
   ├─ 函数声明（提升）
   │  ├─ handleApi / handleAccounts / handleAdmin
   │  ├─ handleApi 内的 authorized / validateSave
   │  ├─ persistDb / sendJson / readBody / readForm
   │  └─ serveStatic / renderDashboard
   │
   ├─ http.createServer(async (req, res) => { ... })   node:http
   │  └─ 只是创建 Server 对象，还没有监听
   │
   ├─ server.listen(PORT, HOST, callback)              node:http
   │  └─ [监听成功回调]
   │     ├─ readCatalogVersion()                       server.js
   │     │  ├─ fs.readFileSync(ServerData/AB/catalog.json)
   │     │  └─ JSON.parse
   │     └─ console.log(banner)
   │
   └─ process.on('SIGINT' | 'SIGTERM', handler)         node:process
      └─ [收到 Ctrl+C / 终止信号]
         ├─ console.log('[cloud] shutting down…')
         ├─ server.close(callback)                      node:http
         └─ callback → process.exit(0)
```

## 1.3 方法明细

| 方法 | 所属 | 被谁调用 | 线程 / 说明 |
| --- | --- | --- | --- |
| `loadDb()` | `server.js`（函数） | 模块顶层 | Node 主线程；同步读盘，启动阶段只做一次 |
| `emptyDb()` / `normalizeDb()` | `server.js` | `loadDb()` | 保证 `accounts`、`players` 两个对象存在 |
| `http.createServer(handler)` | `node:http` | 模块顶层 | 创建服务器对象，**不监听** |
| 匿名 `async (req, res)` | `server.js` | `http` 收到请求时 | 每个请求一次，跑在事件循环 |
| `server.listen(PORT, HOST, cb)` | `node:http` | 模块顶层 | **真正打开 TCP 端口**，进程从此不退出 |
| `readCatalogVersion()` | `server.js` | `listen` 回调、`/api/v1/health` | 读 `ServerData/AB/catalog.json` 给 banner/健康检查用 |
| `console.log(...)` | Node 内置 | `listen` 回调 | 打印 URL / Admin / Database / Accounts / Saves |
| `process.on(signal, handler)` | `node:process` | 模块顶层 | 注册优雅退出 |
| `server.close(cb)` | `node:http` | 信号回调 | 停止接收新连接，等在途请求结束后退出 |

## 1.4 关键点

- **没有 `main()`**：Node 把文件当脚本顺序执行，`server.listen` 一执行就进入事件循环。
- **启动阶段没有调用 `persistDb()`**：`db.json` 只在第一次写操作（注册/上传/管理页）时才落盘；如果只有旧的 `players.json`，迁移发生在内存里，第一次写入时一起写进 `db.json`。
- **热更内容不参与启动**：服务器启动只读 `catalog.json` 用于打印版本，不校验 bundle。
- 监听地址是 `0.0.0.0` 时，同一局域网的其它机器可以用 `http://<本机IP>:8080` 访问。

## 4.5 关键点与分支

- **`_busy` 防重入**：上传中按钮禁用，避免连点发多个 PUT。
- **401**：`apiToken` 与服务端 `API_TOKEN` 不一致。
- **422**：客户端字段非法（正常情况下不会）。
- **404**：GET 时无存档；PUT 不要求先有档。
- **无冲突检测**：服务端只递增 `revision`，不校验客户端版本；后写覆盖先写。
- **离线时**：`cloud.IsConfigured` 为 false（`PlayerSession.IsOnline` 为 false），按钮禁用，不会发请求。

热更分两段：**Start 场景下载/校验内容**（资源热更），**Play 场景加载 DLL 和贴图**（代码/资源生效）。

## 5.1 Start 场景：检查与下载

```text
StartSceneController.Start()
└─ BootFlow()
   └─ [Unity] StartCoroutine(CheckContent)
      └─ StartSceneController.CheckContent(onDone)
         └─ AssetBundleManager.Initialize(config, status, progress)
            ├─ status("读取内置 AB 清单…")
            ├─ AssetBundleManager.ReadCatalog(StreamingAssets/AB/catalog.json)

            │  ├─ File.ReadAllText

            ├─ AssetBundleManager.ValidateCatalogEntries(local, "内置清单")
            │
            ├─ AssetBundleManager.ReadCatalog(persistentDataPath/AB/latest/catalog.json)
            ├─ [cached != null] AssetBundleManager.ValidateCatalogFiles(cached, LatestCacheRoot)
            │  ├─ File.Exists(bundle)
            │  ├─ FileInfo.Length == entry.size
            │  └─ VerifyHash(file, sha256) → SHA256
            │  └─ [失败] LastWarning = "缓存校验失败，忽略缓存"；cached = null

            ├─ AssetBundleManager.FetchCatalog(contentBaseUrl/catalog.json?t=…)
            │  ├─ UnityWebRequest.Get(AddCacheBuster(url))
            │  ├─ request.timeout = 5
            │  ├─ request.SendWebRequest()                 （yield）
            │  ├─ [失败] onError → LastWarning；remote = null
            │  ├─ ParseCatalog
            │  └─ ValidateCatalogEntries(remote)
            │
            ├─ AssetBundleManager.PickHighest(local, cached, remote)
            │  └─ 只比较 buildNumber，取最大
            │
            ├─ [best == remote]
            │  ├─ status("发现新版本 x，准备下载…")
            │  └─ AssetBundleManager.DownloadCatalog(remote, progress, onDone)
            │     ├─ progress(0)
            │     ├─ Directory.CreateDirectory(latest.downloading)
            │     ├─ foreach bundle:
            │     │  ├─ [缓存已有同 hash] VerifyHash + File.Copy + progress
            │     │  ├─ UnityWebRequest.Get(bundle.file?t=…)
            │     │  ├─ downloadHandler = new DownloadHandlerFile(tempFile)
            │     │  ├─ request.SendWebRequest()

            │     │  ├─ VerifyHash(tempFile)
            │     │  ├─ File.Delete(destination)（如存在）
            │     │  ├─ File.Move(tempFile, destination)
            │     │  └─ progress(completedBytes / totalBytes)
            │     ├─ File.WriteAllText(temp/catalog.json, JsonUtility.ToJson(catalog, true))
            │     ├─ Directory.Move(latest → latest.backup)
            │     ├─ Directory.Move(latest.downloading → latest)
```

| 内置 catalog 缺失 | — | `FatalError`，AOT 兜底 |

| `UnityWebRequest.SendWebRequest` | 引擎原生层异步 | 否；协程恢复回主线程 |
| `Node` 的 `fs` 异步写 | libuv 线程池 | 不阻塞事件循环 |
| `console.log` / `JSON.parse`（小对象） | Node 事件循环 | 是（毫秒级） |

# 附录 C：一句话记忆

- **启动服务器**：`node` 执行 `server.js` → `loadDb()` → `server.listen()` → 事件循环。
- **注册**：`Start` → `BootFlow` → `Register` → `AuthRoutine` → `AccountApi.Post` → `handleAccounts` → `persistDb`。
- **登录进游戏**：`Login` → `AuthRoutine` → `EnterOnline` → `LoadScene` → `GameRoot.Start` → `AssetBundleManager.Initialize` → `LoadBootContent` → `TryInitialize` → `GameHud.BindUI` → `AutoLoadCloudSave`。
- **扣血上传**：`OnDamageClicked` → `TakeDamage` → `HotUpdateRuntime.CalculateDamage`；`OnUploadClicked` → `UploadRoutine` → `CreateSnapshot` → `Upload` → `handleApi` → `persistDb`。
- **热更**：`CheckContent` → `AssetBundleManager.Initialize`（catalog 三方仲裁 → 下载 → SHA256 → 原子替换）；`GameRoot.Start` → `LoadBootContent` → `Assembly.Load` → `manifest.heroSprite`。
