> 目标读者：会 C#、没怎么写过 Node.js 的人。

## 0. 先建立整体印象

`server.js` 是一个**普通 Node 进程**：启动 → 读 JSON 数据库 → 监听 8080 → 每个请求进来跑一遍路由函数。

文件从头到尾只有 6 段，按顺序读就是它的执行顺序：

| 行号 | 段落 | 干什么 |
| --- | --- | --- |
| 29–50 | 常量与配置 | 端口、路径、token、MIME 表 |
| 56–121 | JSON 数据库 | 读盘、规范化、原子写盘、`playerId` 生成 |
| 127–206 | HTTP 工具 | 统一响应格式、读请求体、读 catalog、鉴权 |
| 208–240 | 入参校验 | 存档字段、账号密码长度 |
| 246–304 | 账号 API | 注册、登录 |
| 306–399 | 存档 API | 健康检查、`GET/PUT /api/v1/players/:id` |
| 405–601 | 管理页 | 首页 HTML、几个表单 POST |
| 607–656 | 静态内容 | `/ServerData/AB/*` 文件下载 |
| 662–735 | 启动 | `http.createServer`、路由分发、监听、优雅退出 |

一句话概括数据流：

```text
浏览器/Unity ──HTTP──> http.createServer 回调
                          ├─ /            → renderDashboard（HTML）
                          ├─ /admin/*     → handleAdmin（表单）
                          ├─ /api/*       → handleApi（JSON）
                          └─ /ServerData/* → serveStatic（文件流）
                                     │
                                     └─ 读写 CloudServer/data/db.json
```

## 1. JS 速查（写给写 C# 的人）

不要被语法吓到，这个文件只用了下面这些。左边是 JS 写法，右边是它对应的 C# 概念。

| JS | C# 里近似的东西 | 说明 |
| --- | --- | --- |
| `const fs = require('node:fs')` | `using System.IO;` | CommonJS 引入模块；`node:` 前缀表示"内置模块" |
| `const` / `let` | `readonly` / `var` | 这个文件几乎不用 `var` |
| `'use strict';` | 无 | 打开严格模式，拼错变量名会直接报错而不是建全局变量 |
| `` `Hello ${name}` `` | `$"Hello {name}"` | 模板字符串，反引号 |
| `x => x + 1` | `x => x + 1` | 箭头函数，就是 lambda |
| `a?.b` | `a?.b` | 可选链，null 就短路 |
| `a ?? b` | `a ?? b` | 空值合并 |
| `const { account, password } = credentials;` | `var (account, password) = ...` | 解构赋值 |
| `{ ...headers }` | 无 | 展开（浅拷贝/合并对象） |
| `async function f() { await g(); }` | `async Task F() { await G(); }` | 一样是 async/await，但只有**单线程** |
| `for await (const chunk of req)` | `await foreach (var chunk in stream)` | 异步迭代：一块块读请求体 |
| `Object.entries(obj).map(([k, v]) => ...)` | `obj.Select(kv => ...)` | 把对象转成键值对数组 |
| `arr.join('')` | `string.Concat(arr)` | 拼字符串 |
| `Object.fromEntries(new URLSearchParams(body))` | 无直接对应 | 把 `a=1&b=2` 变成 `{a:'1', b:'2'}` |
| `try { } catch (e) { } finally { }` | 同 | 一样 |
| `throw new Error('x')` | `throw new Exception("x")` | 没有受检异常 |
| `Number(x)` / `String(x)` | `int.Parse` / `ToString` | 显式转换 |
| `Number.isInteger(x)` | `x is int` 的近似 | 判断整数 |

几个**和 C# 思维不一样**的点：

1. **没有类型**。所有东西都是对象/值，靠函数名和校验函数（`validateSave`）兜底。
2. **单线程**。`async/await` 不会开线程，只是"等 I/O 时让出"，所以两个请求不会真并行；
   也正因为单线程，`handleAccounts` 里"先查重、再赋值"中间没有 `await`，两个并发注册不可能都成功。
3. **函数是一等公民**。`http.createServer(async (req, res) => {...})` 就是把一个匿名函数当参数传进去。
4. **对象就是字典**。`db.accounts['alice']` 等价于 `Dictionary<string, Account>` 索引器。

## 3. 逐段读

### 3.1 常量与配置（29–50）

```js
const ROOT = path.resolve(__dirname, '..');                    // 项目根目录
const PORT = Number(process.env.PORT || 8080);                 // 环境变量优先
const API_TOKEN = process.env.API_TOKEN || 'dev-token';
const CONTENT_ROOT = path.resolve(process.env.CONTENT_ROOT || path.join(ROOT, 'ServerData'));
const DATA_DIR = path.resolve(process.env.DATA_DIR || path.join(__dirname, 'data'));
const DB_FILE = path.join(DATA_DIR, 'db.json');
const LEGACY_PLAYERS_FILE = path.join(DATA_DIR, 'players.json');
const MAX_BODY = 64 * 1024;                                    // 请求体上限 64 KB
const ID_PATTERN = /^[A-Za-z0-9._-]{1,64}$/;
```

要点：

- `__dirname` 是"当前文件所在目录"，`ROOT` 因此是 `CloudServer/` 的上一级 —— 这样从任何工作目录启动都能找到 `ServerData/`；
- 三个路径都可以用环境变量覆盖（`PORT`、`CONTENT_ROOT`、`DATA_DIR`），`Dockerfile` 就是这么用的；
- `MIME` 表决定静态文件返回的 `Content-Type`，`.bundle` 故意用 `application/octet-stream`。

### 3.2 JSON 数据库（56–121）

```js
function emptyDb() {
  return { schemaVersion: 2, accounts: {}, players: {} };
}
```

数据库就两个字典：`accounts` 按账号名索引，`players` 按 `playerId` 索引。

**`loadDb()`**：有 `db.json` 就读，没有就把旧的 `players.json` 迁移进来。
所以从老版本升级不用手工搬数据。

**`persistDb()`** 是最值得学的一段：

```js
let saveChain = Promise.resolve();

function persistDb() {
  const write = saveChain.then(async () => {
    await fsp.mkdir(DATA_DIR, { recursive: true });
    const temp = `${DB_FILE}.tmp`;
    await fsp.writeFile(temp, JSON.stringify(db, null, 2), 'utf8');
    await fsp.rename(temp, DB_FILE);        // 原子替换
  });

  saveChain = write.catch((error) => {
    console.error('[cloud] failed to persist db.json:', error.message);
  });

  return write;
}
```

三件事：

1. **先写 `.tmp` 再 `rename`**：`rename` 在同一分区上是原子的，进程半路被杀也不会留下半个 JSON；
2. **`saveChain` 串行化写盘**：多个请求同时 `await persistDb()` 时，写操作排队，不会交叉写坏文件；
3. **`catch` 只记日志**：写盘失败不影响已经返回的响应，但下一次写会继续排队。

`playerIdOf`：

```js
function playerIdOf(account) {
  return 'player-' + crypto.createHash('sha256').update(account, 'utf8').digest('hex').slice(0, 12);
}
```

账号名 → 安全的 URL 段。**可预测**，这是本地演示的折中（见第 7 节 Q&A）。

### 3.3 HTTP 工具（127–206）

`sendJson` 是全文唯一的"返回 JSON"出口：

```js
function sendJson(res, status, payload, extraHeaders = {}) {
  const body = JSON.stringify(payload);
  res.writeHead(status, {
    'Content-Type': 'application/json; charset=utf-8',
    'Content-Length': Buffer.byteLength(body),   // 字节数，不是字符数
    'Cache-Control': 'no-store',
    'Access-Control-Allow-Origin': '*',
    ...
  });
  res.end(body);
}
```

- `res.writeHead(status, headers)` 一次写状态行 + 响应头；`res.end(body)` 写正文并结束；
- 手动写 `Content-Length` 可以避免 `chunked` 编码，客户端拿到的长度是确定的；
- CORS 三个头是给"浏览器直连"用的（管理页是同源，其实用不上，但方便你用别的页面调试）。

`readBody` 用异步迭代读请求体，并强制 64 KB 上限：

```js
async function readBody(req) {
  const chunks = [];
  let size = 0;
  for await (const chunk of req) {
    size += chunk.length;
    if (size > MAX_BODY) {
      const error = new Error('request body too large');
      error.statusCode = 413;
      throw error;
    }
    chunks.push(chunk);
  }
  return Buffer.concat(chunks).toString('utf8');
}
```

> 自定义 `statusCode` 挂在 `Error` 上，上层 `catch` 里用 `error.statusCode || 400` 取 —— 这是 JS 里常见的小技巧，
> 等价于 C# 里自定义 `Exception` 类型带一个 `StatusCode` 属性。

`authorized(req)`：

```js
function authorized(req) {
  const header = req.headers.authorization || '';
  const token = header.startsWith('Bearer ') ? header.slice(7) : '';
  if (!API_TOKEN) return true;                     // 没配 token = 关闭鉴权

  const a = Buffer.from(token);
  const b = Buffer.from(API_TOKEN);
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
```

长度必须相等才能调用 `timingSafeEqual`（否则它会直接抛错），所以先比长度。

### 3.4 入参校验（208–240）

```js
function validateSave(body) {
  if (!Number.isInteger(body.hp) || body.hp < 0) return 'hp must be a non-negative integer';
  if (!Number.isInteger(body.maxHp) || body.maxHp < 1 || body.maxHp > 1000000) return '...';
  if (body.hp > body.maxHp) return 'hp cannot exceed maxHp';
  if (typeof body.hotUpdateVersion !== 'string' || body.hotUpdateVersion.length > 80) return '...';
  if (body.schemaVersion !== undefined && body.schemaVersion !== 1) return 'unsupported schemaVersion';
  return null;                                     // null = 通过
}
```

设计模式：**返回错误字符串或 `null`**，调用方 `if (validationError) { sendJson(422, ...) }`。
没有异常、没有 `try`，比抛异常更好读。

### 3.5 账号 API（246–304）

`handleAccounts` 同时挂两个路由：

```js
const isRegister = url.pathname === '/api/v1/accounts/register';
const isLogin = url.pathname === '/api/v1/accounts/login';
if ((!isRegister && !isLogin) || req.method !== 'POST') return false;   // 不是我处理的，交回上层
```

返回 `true` 表示"我处理了"，`false` 表示"继续找别的路由"。这是 Node 里手写路由最省事的写法。

注册：

```js
if (isRegister) {
  if (record) { sendJson(res, 409, { ok: false, error: '用户存在' }); return true; }
  db.accounts[account] = { password, playerId: playerIdOf(account), createdAt: new Date().toISOString() };
  await persistDb();
  sendJson(res, 201, { ok: true, data: { account, playerId: db.accounts[account].playerId } });
  return true;
}
```

**注意"先查重、再赋值"之间没有 `await`** —— 单线程 + 无让出点，所以两个并发注册不可能都成功。
注释里写得很清楚，这是这个实现能省掉锁的原因。

登录：

```js
if (!record || record.password !== password) {
  sendJson(res, 401, { ok: false, error: '账户或密码错误' });
  return true;
}
```

账号不存在和密码错返回同一句话，避免暴露"这个账号存在"。

### 3.6 存档 API（306–399）

`handleApi` 是总入口，顺序很重要：

```js
if (req.method === 'OPTIONS') { sendJson(res, 204, {}); return true; }   // 预检
if (url.pathname === '/api/v1/health' && req.method === 'GET') { ... }   // 健康检查（不需要 token）
if (await handleAccounts(req, res, url)) return true;                    // 账号（不需要 token）

const match = url.pathname.match(/^\/api\/v1\/players\/([^/]+)$/);
if (!match) return false;                                                // 不认识的路径

if (!authorized(req)) { sendJson(res, 401, ...); return true; }          // 从这里开始要 token
```

- **账号接口在鉴权之前**：没登录当然没有 token；
- 存档接口在鉴权之后：`GET`/`PUT` 都要 `Authorization: Bearer dev-token`；
- `playerId` 还要过一遍 `ID_PATTERN`，防止用 `../` 之类的字符串去搞路径；
- `PUT` 时**以 URL 为准**重建对象，请求体里塞的 `playerId` 会被丢弃：

```js
const save = {
  playerId,                                   // ← 来自 URL
  hp: body.hp, maxHp: body.maxHp,
  hotUpdateVersion: String(body.hotUpdateVersion),
  clientTimeUtc: ...,
  schemaVersion: 1,
  serverTimeUtc,
  revision: Number.isInteger(db.players[playerId]?.revision) ? db.players[playerId].revision + 1 : 1,
};
```

`revision` 是服务端自己维护的版本号，客户端目前不参与冲突检测（见第 7 节）。

### 3.7 管理页（405–601）

管理页是**服务端渲染的 HTML**，没有前端框架：

- `GET /` → `renderDashboard(msg, err)` 拼出整页 HTML；
- 表单 `POST /admin/register` 等 → 处理完 `redirect(res, '/?msg=已创建账号 x')`；
- `redirect` 用 **303 See Other**，浏览器会改成 `GET` 跳转，刷新页面不会重复提交；
- 所有插进 HTML 的值都过 `escapeHtml`（`& < > " '`），防 XSS；
- `?msg=` / `?err=` 用 `encodeURIComponent` 编码后再拼 URL。

```js
function redirect(res, location) {
  res.writeHead(303, { Location: location, 'Cache-Control': 'no-store' });
  res.end();
}
```

这段是整个文件里最长的一块（约 200 行），但基本是 HTML/CSS 字符串，读的时候跳过也行。

### 3.8 静态内容（607–656）

给 Unity 下载 AB 用的，两个关键点：

**1）防路径穿越：**

```js
const relative = pathname.slice('/ServerData/'.length);
const target = path.resolve(CONTENT_ROOT, relative);
const contentPrefix = CONTENT_ROOT.endsWith(path.sep) ? CONTENT_ROOT : CONTENT_ROOT + path.sep;
if (target !== CONTENT_ROOT && !target.startsWith(contentPrefix)) {
  sendJson(res, 403, { ok: false, error: 'forbidden' });
  return;
}
```

`path.resolve` 会把 `../` 归一化，再用前缀判断"结果必须还在 `ServerData/` 下面"。
`/ServerData/../../Windows/win.ini` 会在这一步被挡掉。

**2）禁止缓存 + 流式返回：**

```js
res.writeHead(200, {
  'Content-Type': MIME[extension] || 'application/octet-stream',
  'Content-Length': stat.size,
  'Cache-Control': 'no-cache, no-store, must-revalidate',
});
if (req.method === 'HEAD') { res.end(); return; }
fs.createReadStream(target).pipe(res);
```

热更内容必须每次重新校验，所以显式禁缓存；大文件用流，不整个读进内存。

### 3.9 启动（662–735）

```js
const server = http.createServer(async (req, res) => {
  const started = Date.now();
  try {
    const url = new URL(req.url || '/', `http://${req.headers.host || 'localhost'}`);

    if (url.pathname === '/' && req.method === 'GET') { /* 管理页 */ return; }
    if (url.pathname.startsWith('/admin/')) { /* 表单 */ return; }
    if (url.pathname.startsWith('/api/')) { /* JSON API */ return; }
    if (req.method === 'GET' || req.method === 'HEAD') { /* 静态文件 */ return; }

    sendJson(res, 405, { ok: false, error: 'method not allowed' });
  } catch (error) {
    console.error('[cloud] unhandled error:', error);
    if (!res.headersSent) sendJson(res, 500, { ok: false, error: 'internal server error' });
    else res.destroy();
  } finally {
    console.log(`[cloud] ${req.method} ${req.url} -> ${res.statusCode} (${Date.now() - started}ms)`);
  }
});
```

路由就是**按前缀一路 `if` 下来**，没有中间件、没有 Express。读的时候从上往下对着 URL 走一遍就懂了。

`finally` 里的访问日志格式就是你在终端看到的：

```text
[cloud] POST /api/v1/accounts/register -> 201 (3ms)
```

最后是 `server.listen` 打印 banner（包含当前 `catalog.json` 的版本），以及 `SIGINT/SIGTERM` 的优雅退出。

## 4. 跟着一次请求走

### 4.1 注册

```text
Unity: AccountApi.Register → POST /api/v1/accounts/register  {"account":"123","password":"123"}
  → createServer 回调 → url.pathname 命中 /api/ → handleApi
  → OPTIONS? 否 → health? 否 → handleAccounts → isRegister = true
  → readBody（读 JSON）→ JSON.parse
  → validateCredentials（长度 1–32 / 1–64）
  → db.accounts['123'] 存在？→ 409 {"ok":false,"error":"用户存在"}
  → 不存在：写入 password/playerId/createdAt → await persistDb() → 201
  → Unity 收到 201，弹「注册成功，请登录」
```

### 4.2 登录

```text
POST /api/v1/accounts/login {"account":"123","password":"123"}
  → handleAccounts → isLogin = true
  → record = db.accounts['123']
  → !record 或 password 不等 → 401 {"ok":false,"error":"账户或密码错误"}
  → 相等 → 200 {"ok":true,"data":{"account":"123","playerId":"player-a665a4592042"}}
  → Unity: PlayerSession.EnterOnline(account, playerId) → LoadScene("Play")
```

### 4.3 上传存档

```text
PUT /api/v1/players/player-a665a4592042
Authorization: Bearer dev-token
{"playerId":"...","hp":92,"maxHp":100,"hotUpdateVersion":"1.4.0",...}
  → handleApi → 匹配 players 路由 → authorized() 通过
  → validateSave：hp 是整数、0 ≤ hp ≤ maxHp、版本字符串 ≤ 80
  → 用 URL 的 playerId 重建 save，补 serverTimeUtc，revision = 旧值 + 1
  → db.players[playerId] = save → await persistDb() → 200
```

### 4.4 下载存档

```text
GET /api/v1/players/player-a665a4592042  (Bearer)
  → 没有这条存档 → 404 {"ok":false,"error":"no cloud save for this player"}
  → 有 → 200 {"ok":true,"data":{...},"serverTimeUtc":"..."}
  → Unity: player.ApplyServerHp(data.hp)，状态行「已从云端恢复 79/100」
```

### 4.5 下载热更包

```text
GET /ServerData/AB/catalog.json?t=638...
  → 不是 /admin/、不是 /api/ → GET → serveStatic
  → 前缀检查通过 → fsp.stat → 200 + application/json + 禁止缓存
GET /ServerData/AB/content_boot.bundle?t=...
  → 同上 → application/octet-stream → 流式返回 201476 字节
```

## 5. API 一览

| 方法 | 路径 | 鉴权 | 请求体 | 成功 | 失败 |

## 6. 数据模型

```json
{
  "schemaVersion": 2,
  "accounts": {
    "123": {
      "password": "123",
      "playerId": "player-a665a4592042",
      "createdAt": "2026-11-03T10:57:16.446Z"
    }
  },
  "players": {
    "player-a665a4592042": {
      "playerId": "player-a665a4592042",
      "hp": 79,
      "maxHp": 100,
      "hotUpdateVersion": "1.4.0",
      "clientTimeUtc": "2026-11-03T10:58:20.5654654Z",
      "schemaVersion": 1,
      "serverTimeUtc": "2026-11-03T10:58:20.575Z",
      "revision": 2
    }
  }
}
```

| 字段 | 谁写的 | 含义 |
| --- | --- | --- |
| `accounts[].password` | 客户端提交，服务端原样存 | **明文**（教学用，生产必须哈希） |
| `accounts[].playerId` | `playerIdOf(account)` | 存档主键，也是 URL 里的 id |
| `players[].hp` / `maxHp` | 客户端上传，服务端校验范围 | 存档内容 |
| `players[].hotUpdateVersion` | 客户端上传 | 上传时运行的代码版本，用来排查 |
| `players[].clientTimeUtc` | 客户端 | 客户端时间，仅记录 |
| `players[].serverTimeUtc` | 服务端覆盖 | 服务端时间，可信 |
| `players[].revision` | 服务端自增 | 每次 `PUT` / 管理页改 HP 都 +1 |

## 7. 常见疑问

**Q：为什么不用 Express？**
A：零依赖是刻意的教学选择。Express 会把路由、body 解析、静态文件都藏起来；这里全部手写，正好看清"一个请求怎么进来、怎么出去"。

**Q：单线程怎么扛并发？**
A：这个 Demo 的并发就是"几个人点按钮"。Node 的事件循环足以处理；真正的风险是**同步读大文件**（`fs.readFileSync` 只在启动读库和 `readCatalogVersion` 里用，文件都很小）。要上规模，先把 `readCatalogVersion` 的结果缓存起来。

**Q：为什么写盘要临时文件 + rename？**
A：直接覆盖时如果进程被杀，`db.json` 会变成半个 JSON，下次启动直接解析失败。临时文件 + `rename` 是"要么全有、要么全无"。

**Q：`revision` 都记了，为什么不校验？**
A：客户端还没实现 `If-Match`。现在任何一次 `PUT` 都会覆盖，属于 last-write-wins。要做冲突检测，就是让 `PUT` 带上 `If-Match: <revision>`，服务端不匹配返回 409。

**Q：`playerId` 为什么可预测？**
A：`playerIdOf` 是 `sha256(account)` 前 12 位，知道账号名就能算出来。配合共享 token，等于"知道账号就能改存档"。生产应改成随机 UUID，并校验 token 与 `playerId` 的归属。

**Q：`OPTIONS` 返回 204，为什么还带 `{}`？**
A：`sendJson` 统一带 body，204 按 HTTP 规范不应该有 body。浏览器/UnityWebRequest 都不会因此出错，但严格来说这是个瑕疵。

**Q：管理页为什么没有登录？**
A：只监听本机的演示服务，README 里写明了"无鉴权，本地演示用"。部署到公网前必须先加认证。

**Q：改了接口，Unity 那边要改哪里？**
A：客户端在 `Assets/Scripts/Baseline/Core/AccountApi.cs`（账号）和 `CloudSyncService.cs`（存档）。
两边用 `JsonUtility` 映射，字段名必须和这里的 `data` 完全一致。

## 8. 想改的时候改哪里

| 想做的事 | 改哪里 |
| --- | --- |
| 换端口 / 换数据目录 | 环境变量 `PORT`、`DATA_DIR`，不用改代码 |
| 关闭 token 校验 | 启动时 `API_TOKEN=""` |
| 加一个 `GET /api/v1/health` 的字段 | `handleApi` 里 health 那一段 |
| 加一个新接口（比如排行榜） | `handleApi` 里加一个 `if (url.pathname === ...)`，记得决定"要不要 token" |
| 存档加字段（比如金币） | `validateSave` 加校验 + `PUT` 里加字段 + Unity 的 `PlayerSave` 加同名字段 |
| 密码改成哈希 | `handleAccounts` 注册时 `crypto.scryptSync(password, salt, 64)`，登录时比较结果；老数据要迁移 |
| 换成真正的数据库 | 把 `loadDb` / `persistDb` 换成 SQLite/Postgres，其余函数不用动 |
| 加登录态（JWT） | 登录成功后签发，`authorized()` 里改验证方式 |
| 管理页加功能 | `handleAdmin` 加一个 `POST` 分支，`renderDashboard` 里加一段 HTML |

## 9. 一页纸记住

```text
1 个进程，5 个内置模块，2 张表（accounts / players）
每个请求：URL → 前缀路由 → 校验 → 改内存对象 → 原子写盘 → 返回 JSON
账号接口不需要 token；存档接口要 Bearer；静态目录要防 ../ 穿越
```

如果这四行你能自己讲出来，`server.js` 就没有黑盒了。
