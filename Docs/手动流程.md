# 手动流程：改代码 / 换贴图 / 打包 / 热更 / 回退

> 工程里已经没有任何自定义编辑器菜单，`Assets/Scripts/Editor/` 也不存在（连"打 AB"的入口都没有）。
> 每一步都能看到中间产物，出错也能定位到具体哪一环；AB 用你自己选的方式打，产物和字段按第 1.4 节的约定即可。

| 位置 | 是什么 | 谁来改 |

## 1. 打第一个包（V1 基线）

### 1.1 编译热更 DLL

菜单 `HybridCLR → CompileDll → Win64`（HybridCLR 8.15 的菜单名是 `Win64`，没有 `StandaloneWindows64` 这一项）

产物：`HybridCLRData/HotUpdateDlls/StandaloneWindows64/HotUpdate.dll`
（`HybridCLRData/` 已在 gitignore 里，不进仓库）

### 1.2 拷成 TextAsset

资源管理器里把上面那个 `HotUpdate.dll` 复制到 `Assets/HotUpdate/Build/`（**目录不存在就自己新建**），**重命名为 `HotUpdate.dll.bytes`**。

`.bytes` 后缀让 Unity 把它当 `TextAsset` 导入，运行时才能 `Assembly.Load(bytes)`。
改名后回 Unity 等一下重新导入。

### 1.3 打 AssetBundle 标签

Project 窗口选中资源 → Inspector **最下方** 的 `AssetBundle` 区域：

| 资源 | AssetBundle 名字 |
| --- | --- |
| `Assets/Art/Hero.png` | `hotupdate_assets.bundle` |
| `Assets/HotUpdate/Build/HotUpdate.dll.bytes` | `hotupdate_code.bundle` |

（Variant 留空。）

### 1.4 打 AB（工程不提供工具）

`BuildPipeline.BuildAssetBundles` 只能在编辑器里跑，而工程里已经没有任何菜单/脚本入口。你自己选一种方式（自写编辑器脚本、AssetBundle Browser、命令行 batchmode 都行），产物满足下面约定即可：

- 输出目录：`ServerData/AB/`
- 文件名：`hotupdate_code.bundle`、`hotupdate_assets.bundle`（bundle 名和文件名保持一致，catalog 按文件名找）
- 每个 bundle 里的资源名：`HotUpdate.dll`、`Hero`
- 打包选项建议：`ChunkBasedCompression | ForceRebuildAssetBundle`，目标平台 `StandaloneWindows64`

打完用任意工具算 sha256（PowerShell 也行）：

```powershell
Get-FileHash ServerData\AB\hotupdate_code.bundle -Algorithm SHA256
Get-FileHash ServerData\AB\hotupdate_assets.bundle -Algorithm SHA256
```

这两个 `sha256` 和文件 `size` 就是下面 catalog 要抄的数。

### 1.5 手写 catalog.json

新建/覆盖 `ServerData/AB/catalog.json`（模板，把 sha256 和 size 换成你刚才看到的）：

```json
{
  "schemaVersion": 1,
  "buildNumber": 1,
  "contentVersion": "1.0.0",
  "builtAtUtc": "2026-01-01T00:00:00.0000000Z",
  "bundles": [
    { "name": "hotupdate_code.bundle", "file": "hotupdate_code.bundle",
      "sha256": "把 console 里的值粘进来", "size": 3902, "dependencies": [] },
    { "name": "hotupdate_assets.bundle", "file": "hotupdate_assets.bundle",
      "sha256": "把 console 里的值粘进来", "size": 105515, "dependencies": [] }
  ],
  "assets": [
    { "key": "hotupdate_dll", "bundle": "hotupdate_code.bundle", "asset": "HotUpdate.dll", "type": "TextAsset" },
    { "key": "hero_sprite", "bundle": "hotupdate_assets.bundle", "asset": "Hero", "type": "Sprite" }
  ]
}
```

规则：

- `buildNumber` 是唯一的"新旧"判据，**只能递增**；
- `contentVersion` 只给人看（建议 `1.0.<buildNumber-1>`）；
- `sha256` 必须和文件一致，否则客户端会判定下载失败并回退。

### 1.6 同步内置内容

把 `ServerData/AB/` 里的 **两个 `.bundle` + `catalog.json`** 复制到 `Assets/StreamingAssets/AB/`。

不要复制 `AB` 和 `AB.manifest`（那是 BuildPipeline 的副产物）。

### 1.7 打 Player

1. 菜单 `HybridCLR → Generate → All`（生成 AOT 裁剪 / bridge / 补充元数据）
2. `File → Build Profiles` → Windows x86_64 → `Build`

注意：**打包时会把当时的 `StreamingAssets/AB` 烤进包**。所以内置基线要在发 V2 之前打。

### ✅ 验收

双击 `Builds/Windows/EmberGuardian.exe`（先起 `node CloudServer/server.js`）：

- `代码 1.0.0 | 内容 1.0.0 | builtin`
- 扣血 `-7`，HP 100 → 93
- 机器人青色
- 上传云端成功
- 如果这个账号云端已有存档，进 Play 会先自动恢复成云端 HP，不会从 100 开始（想从 100 验证就换账号，或按第 4 节清掉云端存档）

## 2. 发热更（V2）

### 2.1 手改代码

`Assets/Scripts/HotUpdate/DemoHotUpdateModule.cs`，改三处：

```csharp
public string DisplayVersion => "1.2.0";   // 1.0.0 -> 1.2.0，用来在界面上证明换的是新 DLL
public int DamageBonus => 9;                // 2 -> 9
public int CalculateDamage(int baseDamage, int currentHp, int maxHp)
{
    int raw = baseDamage + DamageBonus;
    if (maxHp > 0 && currentHp <= Mathf.CeilToInt(maxHp * 0.35f))
    {
        raw *= 2;                           // 新增：残血狂暴
    }
    return Mathf.Clamp(raw, 1, Mathf.Max(1, currentHp));
}
```

### 2.2 手换贴图

把金色机器人 png（`Tools/Art/HeroHotfix.png`，或你自己画的）拖到 `Assets/Art/Hero.png` 覆盖。

覆盖后确认导入设置没变：`Texture Type = Sprite (2D and UI)`、`Sprite Mode = Single`、`Pixels Per Unit = 100`、`Alpha Is Transparency` 打勾。

### 2.3 重新编译 + 重打 AB

重复 **1.1 → 1.2 → 1.4**（标签 1.3 已经设过，不用重设；但如果换了新文件要重新检查）。

### 2.4 手改 catalog

```json
"buildNumber": 2,
"contentVersion": "1.0.1",
```

并把两个 bundle 的 `sha256` / `size` 换成新的。

### 2.5 只更新服务器

把 `ServerData/AB/` 里的两个 bundle + catalog 覆盖过去即可。

**不要**动 `Assets/StreamingAssets/AB/`，**不要**重打 Player —— 这就是热更的意义。

### 2.6 重启游戏

关掉 exe 再启动：

1. Start 页出现进度条 `下载热更 xx%`；
2. 完成后进 Play：`代码 1.2.0 | 内容 1.0.1 | cache`
3. 扣血 `-14`，HP 100 → 86
4. 机器人金色

## 3. 回退到 V1

### 3.1 改回代码和贴图

- `DemoHotUpdateModule.cs` 改回 `1.0.0` / `+2` / 去掉狂暴分支；
- `Hero.png` 换回青色（`Tools/Art/HeroDefault.png`）。

### 3.2 重新编译 + 重打 AB

重复 1.1、1.2、1.4。

### 3.3 catalog 用**更大的版本号**发旧内容

```json
"buildNumber": 3,
"contentVersion": "1.0.2",
```

铁律：

- **不能**把 buildNumber 改回 1 或 2 —— 已经缓存了 2 的客户端因为 `2 > 1` 会继续跑 V2，只有新用户看到 V1；
- 不能点"重置计数器"之类的操作（已删）；
- 回退 = 用更高版本号发旧内容。

### 3.4 重启游戏

`代码 1.0.0 | 内容 1.0.2 | cache`，扣血 `-7`，机器人青色。

## 4. 想彻底重来（清缓存）

客户端缓存目录：

```text
%USERPROFILE%\AppData\LocalLow\DefaultCompany\HotUpdate+CloudStorage\AB
```

删掉整个 `AB` 文件夹 → 下次启动回到内置内容。
注意 Editor 的 Play Mode 和 exe 共用这个目录。

云端存档在 `CloudServer/data/players.json`。要清空它必须**先停 node、删文件、再启动** —— 只删文件的话 node 内存里还留着旧数据，下一次请求会把它写回来。

## 5. 常见错误对照

| 现象 | 原因 |
| --- | --- |
| 启动报「找不到或无法解析 ...\StreamingAssets\AB\catalog.json」 | 内置 AB 目录被删或没同步。把 `ServerData/AB` 下的 `catalog.json` + 两个 `.bundle` 复制回 `Assets/StreamingAssets/AB` |
| 进 Play 后 HP 不是 100 | 正常：自动恢复了云端存档。想从 100 开始就换账号，或按第 4 节清 `players.json`（先停 node） |
| `CODE AOT fallback` | `.bytes` 没拷对 / 标签没打 / catalog 的 `asset` 名字不对 |
| 有进度条但版本没变 | 下载校验失败回退缓存；看 Player.log 里 `SHA256 校验失败` |
| 图是青色但代码是 1.2.0 | 只更新了 code bundle，`hotupdate_assets.bundle` 没换 |
| 上传 401 | `appconfig.json` 的 `apiToken` 和服务端 `API_TOKEN` 不一致 |
| 启动就崩 | `HotUpdate.dll` 和 AOT 的接口对不上（改了 `IHotUpdateModule` 就必须重打 Player） |

日志位置：

- Editor：Console
- exe：`%USERPROFILE%\AppData\LocalLow\DefaultCompany\HotUpdate+CloudStorage\Player.log`
