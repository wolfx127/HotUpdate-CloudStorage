# 手动流程：改代码 / 换贴图 / 打包 / 热更 / 回退

> 内容打包已内置菜单：`HotUpdate → 1. Build Content`（日常热更）/ `2. Build Content + Sync Baseline`（新基线）。
> 资源身份由 `Assets/HotUpdate/ContentManifest.asset` 的直接引用决定，**不再使用 AB 标签，也不需要手写 catalog**。
>
> 本文按当前工程状态写（`buildNumber = 16`、`contentVersion = 1.0.15`、代码 `1.4.0`、扣血 `-8`）。
> 数字只从两个地方来：`ServerData/AB/catalog.json`（内容）和 `HotUpdateModule.cs`（代码）。

---

## 0. 先认清 6 个位置

| 位置 | 是什么 | 谁来改 |
| --- | --- | --- |
| `Assets/Scripts/HotUpdate/HotUpdateModule.cs` | 热更代码（伤害公式、版本号） | **你手改** |
| `Assets/HotUpdate/ContentManifest.asset` | 内容清单：直接引用「DLL」和「Hero 贴图」 | 菜单首次自动创建；换**新文件**时手动拖引用 |
| `Assets/Art/ChineseHero.png` | 热更贴图（**当前 SO 指向它**，不是 `Hero.png`） | **你手换** |
| `Assets/HotUpdate/Build/HotUpdate.dll.bytes` | 编译出来的 DLL，伪装成 TextAsset | 构建菜单自动生成，不要手改 |
| `ServerData/AB/` | **服务器**上的热更内容（运行时从 `http://127.0.0.1:8080/ServerData/AB` 拉） | 发布时覆盖 |
| `Assets/StreamingAssets/AB/` | 随包**内置**的初始内容（只读，改它不会影响已发布的包） | 菜单 2 自动同步 |

约定：代码只读 `ContentManifest` 的字段；资源身份**不看标签，也不看 catalog key**。

> `Assets/HotUpdate/Build/` 里还有一份 `HotUpdateDemo.dll.bytes`，那是早期方案的产物，现在没有任何地方引用它，别拖进 SO。

## 1. 打第一个包（V1 基线）

### 1.1 准备内容

| 内容 | 位置 |
| --- | --- |
| 热更代码 | `Assets/Scripts/HotUpdate/HotUpdateModule.cs` |
| 热更贴图 | `Assets/Art/ChineseHero.png`（当前 SO 引用），或任意 Sprite |
| 内容清单 | `Assets/HotUpdate/ContentManifest.asset`（第一次构建自动创建） |

### 1.2 一键构建

菜单 `HotUpdate → 2. Build Content + Sync Baseline`：

1. 先读旧 `catalog.json` 的 `buildNumber`（读 `ServerData/AB`，没有就读 `Assets/StreamingAssets/AB`）；
2. `CompileDllCommand.CompileDll` 编译 `HotUpdate.dll` → 覆盖 `Assets/HotUpdate/Build/HotUpdate.dll.bytes`（路径固定，GUID 不变）；
3. 打开/创建 `ContentManifest.asset`，自动写 `hotUpdateDll`；
4. 清空并重建 `ServerData/AB`，用 `AssetBundleBuild.assetNames` 显式打 `content_boot.bundle`（SO + DLL + Hero）；
5. `buildNumber + 1`，重算 `sha256` / `size`，写 `ServerData/AB/catalog.json`；
6. 同步 `catalog.json` + `content_boot.bundle` 到 `Assets/StreamingAssets/AB`。

检查：

- `ContentManifest.asset` 的 `hotUpdateDll` / `heroSprite` 都非空；
- `catalog.json` 只有 `buildNumber` / `contentVersion` / `builtAtUtc` / `bundles`，**没有 `assets` 数组**；
- `ServerData/AB` 里还会有 `AB`、`AB.manifest`、`content_boot.bundle.manifest`，那是 `BuildPipeline` 的副产物，服务器可以不发（发了也无害）；
- 资源上的旧 AB 标签会被忽略（构建只警告，建议清空）。

### 1.3 打 Player

1. 菜单 `HybridCLR → Generate → All`（生成 AOT 裁剪 / bridge / 补充元数据）；
2. `File → Build Profiles` → Windows x86_64 → `Build`。

注意：**打包时会把当时的 `StreamingAssets/AB` 烤进包**。所以内置基线要在发下一版之前打。

### ✅ 验收（当前 build 16 的实际值）

先起 `node CloudServer/server.js`，再双击 `打包/HotUpdate+CloudStorage.exe`：

- `代码 1.4.0 | 内容 1.0.15 | builtin`（首次，或清过缓存）
- 扣血 `-8`，HP 100 → 92
- 机器人是 `ChineseHero` 那张图
- 上传云端成功（`CloudServer/data/db.json` 里有对应 `playerId`）
- 如果这个账号云端已有存档，进 Play 会先自动恢复成云端 HP，不会从 100 开始（想从 100 验证就换账号，或按第 4 节删掉存档）
- 第二次启动时是 `内容 1.0.15 | cache`（说明走了上一次装好的包）

## 2. 发热更（换图 / 改代码）

### 2.1 改内容

- **改代码**：`Assets/Scripts/HotUpdate/HotUpdateModule.cs`，改 `DisplayVersion` / `DamageBonus` / `CalculateDamage`；
- **换图**：
  - 覆盖 SO 当前引用的那张图（现在是 `Assets/Art/ChineseHero.png`）→ 不用动 SO；
  - 换成新文件（GUID 变了）→ 打开 `ContentManifest.asset`，把新 Sprite 拖进 `heroSprite`；
  - **换 `Assets/Art/Hero.png` 不会生效**，因为它没有被 SO 引用。

### 2.2 一键构建（不要按 2）

菜单 `HotUpdate → 1. Build Content`：编译 DLL + 自动绑定 SO + 打 `content_boot.bundle` + `buildNumber + 1`。

只更新 `ServerData/AB`，**不动** `Assets/StreamingAssets/AB`。

### 2.3 发布

把 `ServerData/AB/` 下的 `content_boot.bundle` + `catalog.json` 覆盖到服务器。

**不要**重打 Player —— 这就是热更的意义。

### 2.4 重启游戏

关掉 exe 再启动：

1. Start 页出现进度条 `下载热更 xx%`；
2. 完成后进 Play：`代码 1.4.x | 内容 1.0.16 | cache`
3. 扣血是 `5 + DamageBonus`（改后值）
4. 贴图变成你换的那张

## 3. 回退到旧内容

### 3.1 改回内容

- `HotUpdateModule.cs` 改回旧版本号 / 旧公式；
- 贴图换回旧图（同一路径覆盖则不用动 SO）。

### 3.2 重新构建

菜单 `HotUpdate → 1. Build Content`。

### 3.3 版本号必须继续递增

菜单会自动 `buildNumber + 1`，**不要**手工改小：

- 已经缓存了高版本号的客户端不会降级（`PickHighest` 只在 `buildNumber` 更大时才换）；
- 回退 = 用更高版本号发旧内容。

### 3.4 重启游戏

`代码 1.0.0 | 内容 1.0.x | cache`，扣血回到旧值。

## 4. 想彻底重来（清缓存 / 清库）

客户端缓存目录：

```text
%USERPROFILE%\AppData\LocalLow\DefaultCompany\HotUpdate+CloudStorage\AB
```

删掉整个 `AB` 文件夹 → 下次启动回到内置内容。
注意 Editor 的 Play Mode 和 exe 共用这个目录，`Player.log` 也在这个目录下。

账号和云端存档都在 `CloudServer/data/db.json`（管理页 <http://127.0.0.1:8080> 可以直接建账号、删账号、改/删存档）。
要清空整个数据库必须**先停 node、删文件、再启动** —— 只删文件的话 node 内存里还留着旧数据，下一次请求会把它写回来。

## 5. 常见错误对照

| 现象 | 原因 |
| --- | --- |
| 启动报「找不到或无法解析 ...\StreamingAssets\AB\catalog.json」 | 内置 AB 目录被删或没同步。把 `ServerData/AB` 下的 `catalog.json` + `content_boot.bundle` 复制回 `Assets/StreamingAssets/AB`，或重跑菜单 2 |
| 进 Play 后 HP 不是 100 | 正常：自动恢复了云端存档。想从 100 开始就换账号，或在管理页删掉这条存档 |
| `代码 AOT fallback` | `ContentManifest.hotUpdateDll` 为空 / `content_boot.bundle` 里没有 DLL / SO 没绑定 |
| 换图没生效 | 改的不是 `heroSprite` 指向的图（当前是 `ChineseHero.png`），或者没重跑菜单 1 |
| 有进度条但版本没变 | 下载校验失败回退缓存；看 `Player.log` 里的 `SHA256 校验失败` |
| `[Boot] 未应用热更贴图` | `ContentManifest.heroSprite` 为空，或 `GameRoot.heroRenderer` 没绑 |
| 看不到 `[AB] 已加载 ContentManifest` | `content_boot.bundle` 没打进去，或 catalog 还是旧的 |
| 上传 401 | `appconfig.json` 的 `apiToken` 和服务端 `API_TOKEN` 不一致 |
| 启动就崩 | `HotUpdate.dll` 和 AOT 的接口对不上（改了 `IHotUpdateModule` 就必须重打 Player） |
| 构建后 `ServerData/AB` 是空的 | 菜单先清目录再打；中途编译/打包报错就会留下空目录，修完错误重跑菜单 1 即可（`buildNumber` 只在成功写 catalog 时才前进） |
| 菜单报「没有编出 …\HotUpdate.dll」 | HybridCLR 编译失败，看 Console 的编译错误；先把 `HybridCLR → Installer` 装好 |

日志位置：

- Editor：Console
- exe：`%USERPROFILE%\AppData\LocalLow\DefaultCompany\HotUpdate+CloudStorage\Player.log`
